## Блокнот

Шаги: классы и дизъюнктность, свойства и их характеристики, индивиды из корпуса и журнала, аксиомы и правило 6.2, сохранение и просмотр в Protégé, запуск машины вывода, те же выводы своими руками (правила Хорна, матрица, распространение классов), строка журнала с ошибкой и проверка непротиворечивости, чего в выводе нет, агент с онтологией, вариант по математике.

Нужны пакеты `owlready2` (версия 0.46, она проверена с Java 8–24, версия 0.51 требует Java 25) и `rdflib` и Java для машины вывода Pellet. После установки пакетов ядро блокнота перезапускается, иначе машина вывода падает с `NoClassDefFoundError`. Модель для агента шага 10 задаётся в ячейке «Модель: настройка» в начале блокнота: ключ, адрес сервера и имя модели прописаны явно, по умолчанию локальная Ollama с моделью `qwen-agent`, там же место для облачного ключа. Если сервер не отвечает, шаг 10 печатает записанный протокол, остальные шаги от модели не зависят. Файл `data/review.owl` открывается в Protégé: вкладки Classes, Object properties, Individuals, затем Reasoner → Pellet → Start reasoner. Запуск блокнота из этой папки: `python3 -m notebook`.

## Задание 2. Онтология

Задание продолжает задание 1 лекции 1 на той же области: корпус и карта уже есть, новый материал искать не нужно. Образец выполненного задания: папка `../lecture_3/starter/`, файлы `kg/ontology.ttl`, `kg/ONTOLOGY.md`, `src/build_ontology.py`.

**Что получается.** Та же область, записанная на языке OWL, выведенный машиной факт и объяснение противоречия.

### Коротко

| Шаг | Что сделать | Файл | Как понять, что готово |
|---|---|---|---|
| 1 | принять шесть решений: классы, свойства, дизъюнктность, ограничения, индивиды, противоречие | бумага | каждая связь «подкласс» читается фразой «каждый A является B» |
| 2 | записать онтологию | `kg/ontology.ttl` | не меньше 6 классов с иерархией в три уровня, 3 свойств, 2 ограничений, есть дизъюнктность, 5–8 индивидов из корпуса |
| 3 | сохранить файл и запустить машину вывода | `src/build_ontology.py` | противоречий нет. Появился факт, которого нет среди записанных |
| 4 | внести намеренную ошибку в свежую копию и прочитать объяснение | там же | машина сообщила о противоречии и назвала участников |
| 5 | описать модель | `kg/ONTOLOGY.md` | пять разделов: классы, свойства, высказывания, выведенный факт, противоречие |
| 6 | добавить словарь классов и запись в журнал | `AGENTS.md`, `diary.md` | словарь на месте |
| 7 | проверить | `python3 scripts/check_l2.py` | все пункты зачтены |

### Подробно

**Шесть решений** принимаются до записи, на бумаге: какие классы (значения столбца «тип» корпуса почти всегда становятся классами), какие свойства (связи из карты), что дизъюнктно (одна сущность не может быть двух классов сразу), какие ограничения (у требования есть хотя бы один раздел, у рецензии ровно одна статья), какие индивиды (строки корпуса почти всегда индивиды), какое противоречие внести намеренно. Каждая связь «подкласс» проверяется фразой «каждый A является B».

**Онтология `kg/ontology.ttl`.** Не меньше 6 классов с иерархией в три уровня, не меньше 3 свойств с областями определения и значений, не меньше 2 ограничений, объявленная дизъюнктность, 5–8 индивидов из корпуса со связями между ними. Записывать можно как в блокноте этой лекции классами Python через Owlready2 с сохранением в файл, либо текстом Turtle по образцу `../lecture_3/starter/kg/ontology.ttl`.

**Машина вывода.** Сначала сохранить файл, затем `python3 src/build_ontology.py`. Ожидаемый итог: противоречий нет, и появился факт, которого среди записанных не было (например, зависимость, полученная по транзитивности, или класс, в который индивид попал по определению). Затем внести намеренную ошибку в свежую копию онтологии и прочитать объяснение машины: она должна назвать участников противоречия. Ошибка вносится в копию, рабочий файл остаётся чистым.

**Описание `kg/ONTOLOGY.md`.** Пять разделов: классы, свойства, высказывания (что записано об индивидах), выведенный факт, противоречие. В разделы о выводе и противоречии записывается то, что машина выдала на самом деле, дословно.

**Словарь классов** добавляется в `AGENTS.md`, чтобы агент знал термины области, и делается запись в `diary.md`.

**Проверка.** `python3 scripts/check_l2.py`: 20 пунктов, среди них число классов, свойств, ограничений, дизъюнктность, индивиды и связи между ними, непротиворечивость по машине вывода, разделы описания. Без Java пункт о машине вывода пропускается с пометкой.

**Что сдаётся.** Папка задания 1, дополненная файлами `kg/ontology.ttl`, `kg/ONTOLOGY.md`, `src/build_ontology.py`, словарём классов в `AGENTS.md` и записью в `diary.md`. Оба скрипта проверки зачитывают все пункты. По желанию `src/agent_my.py` переделывается под свою область: заменить загрузку данных и `check_rules`, остальное остаётся.

### Три правила, которые снимают большинство ошибок

- Строка корпуса почти всегда индивид. Значение столбца «тип» почти всегда класс.
- Файл онтологии сохраняется до запуска машины вывода. Ошибка вносится в свежую копию.
- В описание записывается то, что машина выдала на самом деле.
