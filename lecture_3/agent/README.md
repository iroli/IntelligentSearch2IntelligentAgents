# Мини-агент: устройство, цикл, вызов инструментов

Агент это программа, в которой языковая модель выбирает действия, а исполняет их приложение. Модель получает вопрос и список инструментов, просит вызвать нужный, получает результат и так до тех пор, пока не напишет ответ. Ни один факт в ответе не порождается моделью: все факты приходят из инструментов, а модель только решает, что вызвать, и собирает текст.

Запускать из папки занятия, где лежат `data/` и `starter/`.

## Файлы

| Файл | Роль |
|---|---|
| `agent_core.py` | ядро: обращение к модели (`openai_llm`), заглушка (`scripted_llm`) и цикл `run_agent`. От предметной области не зависит |
| `search_bm25.py` | поиск по словам BM25, используется инструментом `search_words` |
| `agent_l1.py` | сборка лекции 1: инструменты над CSV из `data/` |
| `agent_l2.py` | сборка лекции 2: инструменты над онтологией `data/review.owl` |
| `llm_local.py` | выбор модели: переменные окружения, локальная Ollama или записи. Обёртка `tools_first` |
| `ask.py` | вопросы агентам из терминала: `python3 agent/ask.py --help` |
| `Modelfile` | производная модель `qwen-agent` для Ollama с окном контекста 8192 и температурой 0 |

Третья сборка, образец для задания, лежит в `../starter/src/agent_my.py`: тот же цикл над корпусом «Правила зачёта».

## Три части

**Ядро** (`agent_core.py`): цикл и доступ к модели. Оно одинаково для всех сборок.

**Предметная часть** (`agent_l1.py`, `agent_l2.py`, `agent_my.py`): данные, инструменты, их описание для модели, инструкция и вопрос. Каждый файл устроен одинаково, разделы отмечены комментариями:

1. среда: загрузка данных (CSV, онтология, ведомость);
2. инструменты: обычные функции Python с типизированными аргументами;
3. `TOOLS`: описание инструментов для модели в формате JSON Schema, и `IMPL`: словарь «имя → функция»;
4. `SYSTEM` и `QUESTION`: инструкция модели и вопрос по умолчанию;
5. `PLAN` и `RECORD`: план вызовов и записанный ответ для работы без модели.

**Модель**: любая, поддерживающая вызов функций через OpenAI-совместимый API. Локально это Ollama с `qwen-agent`, в облаке любая модель по ключу. Без модели работает заглушка.

Смена предметной области меняет разделы 1–5, ядро остаётся. Это и есть задание: `agent_my.py` показывает результат на двенадцати записях.

## Что модель знает об инструментах

Модель не видит код функций. Она видит только список `TOOLS`: имя, назначение словами и параметры. Пример из `agent_l1.py`:

```python
{"type": "function", "function": {
    "name": "graph_deps",
    "description": "На какие положения транзитивно опирается документ (граф знаний, зависит_от+).",
    "parameters": {"type": "object",
                   "properties": {"doc_id": {"type": "string", "description": "например R65"}},
                   "required": ["doc_id"]}}}
```

Словарь `IMPL` связывает имя из описания с функцией:

```python
IMPL = {"search_words": search_words, "graph_deps": graph_deps,
        "check_rules": check_rules, "lean_check_claims": lean_check_claims}
```

От качества описания зависит, выберет ли модель инструмент и передаст ли верный аргумент. На репетициях модель qwen2.5 7B иногда придумывала аргумент, которого в описании нет (`check_rules(requirement_ids=...)`), и получала ошибку как результат.

## Цикл

Функция `run_agent` в `agent_core.py`, полностью:

```python
def run_agent(question, llm, system, tools, impl, max_steps=8):
    messages = [{"role": "system", "content": system},
                {"role": "user", "content": question}]
    for step in range(1, max_steps + 1):
        m = llm(messages, tools)                      # модель решает, что делать дальше
        messages.append(m)
        calls = m.get("tool_calls") or []
        if not calls:                                 # вызовов нет: это ответ
            print(f"[{step}] ответ модели:\n{m['content']}")
            return messages
        for tc in calls:                              # приложение исполняет вызовы
            name = tc["function"]["name"]
            args = json.loads(tc["function"]["arguments"] or "{}")
            try:
                result = impl[name](**args)
            except Exception as e:                    # ошибка возвращается модели как результат
                result = {"ошибка": f"{type(e).__name__}: {e}"}
            text = json.dumps(result, ensure_ascii=False)
            print(f"[{step}] модель вызвала {name}({args})")
            print(f"    <- {text[:160]}{'…' if len(text) > 160 else ''}")
            messages.append({"role": "tool", "tool_call_id": tc["id"], "content": text})
    print("лимит шагов исчерпан")
    return messages
```

Шаг за шагом:

1. **История** `messages` начинается с инструкции (роль `system`) и вопроса (роль `user`). Вся работа агента это дописывание этой истории.
2. **Ход модели.** Функция `llm` отправляет историю и `tools` на сервер и возвращает одно сообщение модели. В нём либо текст, либо список `tool_calls`: какие инструменты вызвать и с какими аргументами в виде строки JSON.
3. **Ветвление.** Если вызовов нет, текст сообщения и есть ответ, цикл заканчивается. Если вызовы есть, модель ответа ещё не дала и ждёт результатов.
4. **Исполнение.** Для каждого вызова приложение находит функцию по имени в `impl`, разбирает аргументы из JSON и вызывает функцию. Модель к данным не прикасается: функция работает с таблицей или онтологией сама.
5. **Результат в историю.** Возвращённое значение превращается в JSON и дописывается сообщением с ролью `tool` и идентификатором вызова, чтобы модель знала, на какой из своих запросов получила ответ.
6. **Следующий ход.** Модель снова получает всю историю, уже с результатами, и решает: вызвать ещё что-то или писать ответ.
7. **Предел.** Больше `max_steps` ходов цикл не делает: это защита от модели, которая зовёт инструменты без конца.

Ошибка внутри инструмента не останавливает цикл. Исключение перехватывается, и модель получает результат вида `{"ошибка": "TypeError: ..."}`. Так модель узнаёт, что передала лишний аргумент или несуществующий идентификатор, и может исправиться следующим ходом.

Протокол, который печатает цикл, служит для проверки ответа: каждое утверждение ответа должно находиться в строках `<-` с результатами инструментов. Утверждение, которого там нет, модель либо пометила `[не подтверждено]`, либо выдумала.

## Два способа получить ход модели

Цикл получает функцию `llm(messages, tools)` и не знает, что за ней стоит.

**Настоящая модель**, `openai_llm`: один запрос к OpenAI-совместимому API, ответ возвращается словарём. Адрес, ключ и имя модели берутся из переменных `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`. Для локального сервера Ollama эти переменные задаёт `pick_llm` из `llm_local.py`.

**Заглушка**, `scripted_llm(plan, answer)`: выдаёт вызовы из плана по одному, а когда план исчерпан, записанный ответ. Инструменты при этом исполняются по-настоящему, поэтому результаты в протоколе настоящие, записан только порядок вызовов и текст ответа. Так агент работает на машине без модели, и так проверяются сами инструменты.

Запуск файла агента напрямую (`python3 agent/agent_l1.py`) идёт по заглушке с `PLAN` и `RECORD` из раздела 5. Блокноты и `ask.py` подставляют настоящую модель, если она есть, через `run_live_or_record`: при ошибке или истечении времени ожидания прогон повторяется по записи.

## Что добавлено вокруг ядра

В `llm_local.py` лежит то, что нужно для живого показа и не входит в учебное ядро:

- `pick_llm`: выбор модели. Заданы переменные окружения с ключом, значит облако. Иначе опрос локальной Ollama и выбор `qwen-agent` или первой модели с «qwen» в имени. Иначе записи.
- `tools_first`: обёртка над моделью. Пока в истории нет ни одного результата инструмента, ответ без вызовов не принимается, модели возвращается напоминание, и она отвечает ещё раз. Маленькие модели иначе отвечают сразу «[не подтверждено]», не заглянув в данные.
- ограничение времени ответа `LLM_TIMEOUT` (по умолчанию 180 секунд) и обращение к адресу 127.0.0.1 мимо системного прокси.

## Как добавить инструмент

1. Написать функцию Python с типизированными аргументами, возвращающую словарь или список: это станет JSON для модели.
2. Добавить её описание в `TOOLS`: имя, назначение одной фразой, параметры с типами. Имя в описании и ключ в `IMPL` совпадают.
3. Добавить пару «имя → функция» в `IMPL`.
4. Если инструмент нужен обязательно, сказать об этом в `SYSTEM` («Сначала вызови check_consistency»).
5. Дописать вызов в `PLAN` и обновить `RECORD`, чтобы запуск без модели показывал новый инструмент.
6. Проверить без модели (`python3 agent/agent_my.py`), затем с моделью (`python3 agent/ask.py --agent starter "вопрос"`) и сверить ответ с протоколом.

## Команды

```bash
python3 agent/agent_l1.py          # без модели: инструменты настоящие, порядок вызовов и ответ из записи
python3 agent/agent_l2.py          # то же для онтологии, нужны owlready2 и Java
python3 agent/ask.py --status      # какая модель доступна
python3 agent/ask.py "Какие статьи можно выносить на заседание и что мешает остальным?"
python3 agent/ask.py --agent l2 "Нарушает ли статья P3 требования положения о рецензировании?"
python3 agent/ask.py --agent starter "Кто из студентов получает зачёт?"
python3 agent/ask.py --plain "Какие статьи можно выносить?"     # модель без инструментов, для сравнения
```
