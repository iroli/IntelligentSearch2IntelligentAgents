# Практикум по лекциям 1 и 2: материалы для самостоятельной работы

Курс «От интеллектуального поиска к интеллектуальным агентам». В папке лежит всё, что нужно, чтобы повторить примеры первых двух лекций на своей машине и выполнить задания 1 и 2.

## Что здесь лежит

| Что | Где |
|---|---|
| примеры лекции 1: вопрос редактора, поиск по словам, граф зависимостей, правила над журналом, агент | `practice_1_editor.ipynb` |
| примеры лекции 2: онтология, машина вывода, противоречие в данных | `practice_2_ontology.ipynb` |
| оба задания, выполненные на маленькой учебной области | `practice_3_tasks.ipynb` и папка `starter/` |
| мини-агент, папка `agent/` | `agent_core.py` (цикл), `search_bm25.py` (поиск), `agent_l1.py`, `agent_l2.py` (инструменты), `llm_local.py` (выбор модели), `ask.py` (вопросы модели из терминала), `Modelfile` (производная модель для Ollama) |
| рисунок графа | `viz.py` |
| данные примеров | `data/`: журнал рецензий `reviews.csv`, положение о рецензировании `corpus_Aprime_standards.csv`, утверждения статьи P2 `paper_P2_claims.csv`, онтология `review.owl` |
| выполнение заданий 1 и 2 | `ВЫПОЛНЕНИЕ_заданий.md` |
| список пакетов | `requirements.txt` |

## Установка

```bash
pip install -r requirements.txt     # Python 3.8 и новее
java -version                        # Java нужна машине вывода Pellet (блокноты 2 и 3). Если нет: sudo apt install default-jre
```

Проверка, что всё на месте:

```bash
python3 -c "import pandas, rdflib, owlready2, pyshacl, numpy, networkx, matplotlib, openai; print('пакеты есть')"
python3 -m notebook --version        # Jupyter установлен
```

Для заданий 1 и 2 этого достаточно. Модель нужна только для живых ячеек блокнотов и для `ask.py`. Без неё блокноты работают по записям: инструменты вызываются по-настоящему, ответ модели берётся из сохранённого прогона.

**Модель через Ollama** (по желанию, около 2 ГБ на диске):

```bash
curl -fsSL https://ollama.com/install.sh | sh     # установка, см. ollama.com
ollama serve &                                    # сервер, если не запущен
ollama pull qwen2.5:3b                            # базовая модель, один раз
ollama create qwen-agent -f agent/Modelfile       # производная с длинным контекстом
ollama list                                       # в списке qwen2.5:3b и qwen-agent
python3 agent/ask.py --status                     # должно быть: локальная модель qwen-agent через Ollama
```

На процессоре модель 3B отвечает от десяти секунд до минуты на шаг. Если памяти 8 ГБ и больше, лучше `qwen2.5:7b` (см. `agent/Modelfile`). Облачная модель с совместимым API подключается переменными `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL`.

**Protégé** нужен для просмотра онтологии `data/review.owl` и своей онтологии из задания 2: protege.stanford.edu.

## Запуск

```bash
python3 -m notebook           # Jupyter в этой папке, открыть нужный блокнот
```

Если модель установлена, перед занятием один раз `python3 agent/ask.py --warm`: модель загружается в память, печатается время ответа. Блокноты выполняются сверху вниз. Первая ячейка печатает, какая модель используется. Перед живыми ячейками стоит вопрос «Прогноз»: ответьте на него до запуска, затем сравните с результатом.

Вопросы модели из терминала, из папки занятия:

```bash
python3 agent/ask.py --plain "Какие статьи можно выносить?"      # модель без инструментов
python3 agent/ask.py "Какие статьи можно выносить на заседание и что мешает остальным?"   # агент лекции 1
python3 agent/ask.py --agent l2 "Нарушает ли статья P3 требования положения?"             # агент лекции 2
python3 agent/ask.py --agent starter "Кто из студентов получает зачёт?"                    # агент стартового набора
python3 agent/ask.py --agent l1                                    # диалог, пустая строка завершает
```

Агенты без модели, из папки занятия: `python3 agent/agent_l1.py`, `python3 agent/agent_l2.py`. Инструменты вызываются по-настоящему, порядок вызовов и текст ответа берутся из записи.

## Порядок работы

Порядок повторяет логику слайдов: от вопроса редактора к агенту, затем к своим заданиям.

1. Раздел «Установка» выше: пакеты и Java. Модель на этом шаге не обязательна, блокноты работают по записям.
2. `slides_P1.pdf`, слайды 1–10: что строится в курсе, что собирается на занятии, три файла данных. Дальше слайды читаются вместе с блокнотами, у каждого примера своя группа слайдов.
3. `practice_1_editor.ipynb`, примеры 1–4 (слайды 11–30): модель без инструментов и её ошибки, поиск по словам и граф, правила над журналом, агент и чтение протокола. Перед каждой живой ячейкой стоит вопрос «Прогноз», на него отвечают до запуска.
4. `practice_2_ontology.ipynb`, примеры 5–6 (слайды 38–42, 48–51): онтология, машина вывода, строка с ошибкой и противоречие, агент с онтологией. Файл `data/review.owl` параллельно открывается в Protégé.
5. `practice_3_tasks.ipynb`, оба задания на маленькой области (слайды 31–37, 43–47): корпус и граф, пять вопросов, проверка скриптом, онтология, выведенный факт, намеренное противоречие, агент над своим корпусом.
6. `starter/`: четыре команды из `starter/README.md` руками в терминале. Это образец того, что сдаётся.
7. `agent/`: прочитать `agent_core.py` целиком, затем `agent_l1.py` сверху вниз, запустить `python3 agent/agent_l1.py` и сравнить с протоколом из блокнота 1. По желанию установить Ollama по `slides_P1_tools.pdf`, после этого `agent/ask.py` даёт живые ответы.
8. `ВЫПОЛНЕНИЕ_заданий.md`: выбрать свою область, скопировать `starter/`, заменить `kg/corpus.csv` и пройти шаги задания 1, затем задания 2, пока скрипты `check_hw1.py` и `check_l2.py` не зачтут все пункты.

## Задания

Два задания продолжают друг друга и делаются на одной области, которую студент выбирает сам. Задание 1 даёт корпус утверждений и граф зависимостей, задание 2 записывает ту же область онтологией и запускает машину вывода. Вместе они дают то, над чем работает агент занятия: данные со структурой и проверкой. Пошаговый маршрут с критериями готовности лежит в `ВЫПОЛНЕНИЕ_заданий.md`, образец выполненных заданий в `starter/`.

### С чего начать

1. Скопировать папку `starter/` под своим именем, например `my_area/`. В ней уже есть нужная структура: `README.md`, `AGENTS.md`, `diary.md`, `kg/`, `scripts/`, `src/`.
2. Выбрать область. Подходит любой документ или набор текстов, в котором есть утверждения, ссылки одних утверждений на другие и хотя бы один факт, который проверяется по данным: положение или регламент, глава учебника с определениями и теоремами, спецификация, правила конкурса, подборка статей узкой темы. Примеры областей перечислены на слайде 7 лекции 1.
3. Записать область в раздел 1 своего `README.md`: название, источник, почему она подходит.

### Задание 1. Корпус, карта, вопросы

**Что получается.** Таблица утверждений области, карта её типов и связей, пять вопросов с ожидаемыми ответами.

**Корпус `kg/corpus.csv`.** Шесть столбцов, те же, что у положения о рецензировании в `data/corpus_Aprime_standards.csv`: `id`, `тип`, `название`, `формулировка`, `зависит_от`, `источник`. Одна строка это одно утверждение документа. Как превратить фразу документа в строку: задать ей четыре вопроса. Что это (тип: раздел, термин, требование, теорема, определение). Как коротко назвать. На что она ссылается прямо (в `зависит_от` идут только прямые ссылки, через точку с запятой). Где это написано (источник с номером пункта или страницы). Требования: не меньше 30 строк, не меньше 10 с непустым `зависит_от`, не меньше двух типов, у каждой строки источник.

**Карта `kg/MAP.md`.** Какие типы сущностей есть в области и какими связями они соединены. Одна из связей транзитивная: по ней граф даёт цепочки, как `зависит_от` в примере. Образец: `starter/kg/MAP.md`, карта области «Правила зачёта» со схемой связей.

**Пять вопросов** в разделе 2 `README.md`. У каждого тип, ожидаемый ответ и источник. Типы из лекции 1: факт (что написано), зависимость (на что опирается), смысл (норма есть, слова нет), проверка (факт, который считается по данным). Нужны хотя бы вопросы типов факт, зависимость и смысл. Ожидаемый ответ записывается до того, как его даст агент: это эталон для сверки.

**Инструкции агенту и журнал.** В `AGENTS.md` вписать название области, в `diary.md` запись о сделанном: дата, что сделано, что проверено и чем.

**Проверка.** `python3 scripts/check_hw1.py` из корня своей папки. Скрипт проверяет 16 пунктов: объём корпуса, зависимости, типы, источники, заполненность пяти вопросов, наличие файлов. На стартовом наборе он нарочно не зачитывает один пункт, объём корпуса из 12 строк при норме 30: так видно, как скрипт подсказывает, что доделать.

### Задание 2. Онтология

**Что получается.** Та же область, записанная на языке OWL, выведенный машиной факт и объяснение противоречия.

**Шесть решений** принимаются до записи, на бумаге: какие классы (значения столбца «тип» корпуса почти всегда становятся классами), какие свойства (связи из карты), что дизъюнктно (одна сущность не может быть двух классов сразу), какие ограничения (у требования есть хотя бы один раздел, у рецензии ровно одна статья), какие индивиды (строки корпуса почти всегда индивиды), какое противоречие внести намеренно. Каждая связь «подкласс» проверяется фразой «каждый A является B».

**Онтология `kg/ontology.ttl`.** Не меньше 6 классов с иерархией в три уровня, не меньше 3 свойств с областями определения и значений, не меньше 2 ограничений, объявленная дизъюнктность, 5–8 индивидов из корпуса со связями между ними. Записывать можно как в блокноте 2 классами Python через Owlready2 с сохранением в файл, либо текстом Turtle по образцу `starter/kg/ontology.ttl`.

**Машина вывода.** Сначала сохранить файл, затем `python3 src/build_ontology.py`. Ожидаемый итог: противоречий нет, и появился факт, которого среди записанных не было (например, зависимость, полученная по транзитивности, или класс, в который индивид попал по определению). Затем внести намеренную ошибку в свежую копию онтологии и прочитать объяснение машины: она должна назвать участников противоречия. Ошибка вносится в копию, рабочий файл остаётся чистым.

**Описание `kg/ONTOLOGY.md`.** Пять разделов: классы, свойства, высказывания (что записано об индивидах), выведенный факт, противоречие. В разделы о выводе и противоречии записывается то, что машина выдала на самом деле, дословно.

**Словарь классов** добавляется в `AGENTS.md`, чтобы агент знал термины области, и делается запись в `diary.md`.

**Проверка.** `python3 scripts/check_l2.py`: 20 пунктов, среди них число классов, свойств, ограничений, дизъюнктность, индивиды и связи между ними, непротиворечивость по машине вывода, разделы описания. Без Java пункт о машине вывода пропускается с пометкой.

### Что сдаётся

Папка с заданиями целиком: `README.md` с областью и пятью вопросами, `AGENTS.md`, `diary.md`, `kg/corpus.csv`, `kg/MAP.md`, `kg/ontology.ttl`, `kg/ONTOLOGY.md`, `src/build_ontology.py`, `scripts/`. Оба скрипта проверки зачитывают все пункты. По желанию `src/agent_my.py` переделывается под свою область: заменить загрузку данных и `check_rules`, остальное остаётся.

### Три правила, которые снимают большинство ошибок

- Строка корпуса почти всегда индивид. Значение столбца «тип» почти всегда класс.
- Файл онтологии сохраняется до запуска машины вывода. Ошибка вносится в свежую копию.
- В описание записывается то, что машина выдала на самом деле.
