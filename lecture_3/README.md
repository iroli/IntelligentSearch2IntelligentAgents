## Установка

```bash
pip install -r requirements.txt     # Python 3.8 и новее
java -version                        # Java нужна машине вывода Pellet (блокноты 2 и 3). Если нет: sudo apt install default-jre
```

Проверка, что всё на месте:

```bash
python3 -c "import pandas, rdflib, owlready2, pyshacl, numpy, networkx, matplotlib, openai; print('пакеты есть')"
python3 -m notebook --version        # Jupyter установлен
```

Для заданий 1 и 2 этого достаточно. Модель нужна только для живых ячеек блокнотов и для `ask.py`. Без неё блокноты работают по записям: инструменты вызываются по-настоящему, ответ модели берётся из сохранённого прогона.

**Модель через Ollama** (по желанию, около 2 ГБ на диске):

```bash
curl -fsSL https://ollama.com/install.sh | sh     # установка, см. ollama.com
ollama serve &                                    # сервер, если не запущен
ollama pull qwen2.5:3b                            # базовая модель, один раз
ollama create qwen-agent -f agent/Modelfile       # производная с длинным контекстом
ollama list                                       # в списке qwen2.5:3b и qwen-agent
python3 agent/ask.py --status                     # должно быть: локальная модель qwen-agent через Ollama
```

На процессоре модель 3B отвечает от десяти секунд до минуты на шаг. Если памяти 8 ГБ и больше, лучше `qwen2.5:7b` (см. `agent/Modelfile`). Облачная модель с совместимым API подключается переменными `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL`.

**Protégé** нужен для просмотра онтологии `data/review.owl` и своей онтологии из задания 2: protege.stanford.edu.

## Запуск

```bash
python3 -m notebook           # Jupyter в этой папке, открыть нужный блокнот
```

Если модель установлена, перед занятием один раз `python3 agent/ask.py --warm`: модель загружается в память, печатается время ответа. Блокноты выполняются сверху вниз. Первая ячейка печатает, какая модель используется. Перед живыми ячейками стоит вопрос «Прогноз»: ответьте на него до запуска, затем сравните с результатом.

Вопросы модели из терминала, из папки занятия:

```bash
python3 agent/ask.py --plain "Какие статьи можно выносить?"      # модель без инструментов
python3 agent/ask.py "Какие статьи можно выносить на заседание и что мешает остальным?"   # агент лекции 1
python3 agent/ask.py --agent l2 "Нарушает ли статья P3 требования положения?"             # агент лекции 2
python3 agent/ask.py --agent starter "Кто из студентов получает зачёт?"                    # агент стартового набора
python3 agent/ask.py --agent l1                                    # диалог, пустая строка завершает
```

Агенты без модели, из папки занятия: `python3 agent/agent_l1.py`, `python3 agent/agent_l2.py`. Инструменты вызываются по-настоящему, порядок вызовов и текст ответа берутся из записи.

## Порядок работы

Порядок повторяет логику слайдов: от вопроса редактора к агенту, затем к своим заданиям.

1. Раздел «Установка» выше: пакеты и Java. Модель на этом шаге не обязательна, блокноты работают по записям.
2. `slides_P1.pdf`, слайды 1–10: что строится в курсе, что собирается на занятии, три файла данных. Дальше слайды читаются вместе с блокнотами, у каждого примера своя группа слайдов.
3. `practice_1_editor.ipynb`, примеры 1–4 (слайды 11–30): модель без инструментов и её ошибки, поиск по словам и граф, правила над журналом, агент и чтение протокола. Перед каждой живой ячейкой стоит вопрос «Прогноз», на него отвечают до запуска.
4. `practice_2_ontology.ipynb`, примеры 5–6 (слайды 38–42, 48–51): онтология, машина вывода, строка с ошибкой и противоречие, агент с онтологией. Файл `data/review.owl` параллельно открывается в Protégé.
5. `practice_3_tasks.ipynb`, оба задания на маленькой области (слайды 31–37, 43–47): корпус и граф, пять вопросов, проверка скриптом, онтология, выведенный факт, намеренное противоречие, агент над своим корпусом.
6. `starter/`: четыре команды из `starter/README.md` руками в терминале. Это образец.
7. `agent/`: прочитать `agent_core.py` целиком, затем `agent_l1.py` сверху вниз, запустить `python3 agent/agent_l1.py` и сравнить с протоколом из блокнота 1. По желанию установить Ollama по `slides_P1_tools.pdf`, после этого `agent/ask.py` даёт живые ответы.
8. `ВЫПОЛНЕНИЕ_заданий.md`: выбрать свою область, скопировать `starter/`, заменить `kg/corpus.csv` и пройти шаги задания 1, затем задания 2, пока скрипты `check_hw1.py` и `check_l2.py` не зачтут все пункты.

## Если что-то не работает

- `jupyter` не находится: запускать `python3 -m notebook`.
- Машина вывода падает с `OwlReadyJavaError`: проверить `java -version` (нужна Java 8 или новее) и версию пакета: `pip show owlready2` должна дать 0.46. Если в ошибке `UnsupportedClassVersionError` и «class file version 69.0», стоит версия 0.51, её Pellet собран под Java 25: `pip install owlready2==0.46`. После любой установки или смены версии пакета перезапустить ядро блокнота: без этого в памяти остаётся старый список jar-файлов и появляется `NoClassDefFoundError`.
- Ячейка «Модель» пишет, что пакет openai не установлен: `%pip install -r requirements.txt` в ячейке и перезапуск ядра. Ядро блокнота может работать в другом Python, чем терминал.
- Ollama не отвечает при запущенном сервере: прокси в переменных окружения. Проверить `curl --noproxy '*' http://127.0.0.1:11434/api/tags`. Код в этой папке к локальному серверу обращается мимо прокси.
- Модель отвечает без вызова инструментов или уходит в другой язык: так бывает у маленьких моделей. Цикл агента возвращает модели напоминание, повторный запуск обычно помогает.
