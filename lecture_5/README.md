## Установка и запуск

```bash
pip install pandas nltk          # стеммер Snowball входит в nltk, скачивать ничего не нужно
python3 -m notebook              # открыть demo_lecture5.ipynb
```

Блокнот выполняется сверху вниз и не требует модели: шаг с агентом идёт по записи, инструмент поиска вызывается по-настоящему. Проверка: `python3 -c "from nltk.stem.snowball import SnowballStemmer; print(SnowballStemmer('russian').stem('рецензии'))"` печатает `реценз`.

## Задание 4

Первая часть задания модуля 2. Выполняется на корпусе `kg/corpus.csv` из задания 1 в той же папке, где лежат задания 1–3. Выборка, собранная здесь, служит заданиям лекций 6–8.

**Что получается.** Индекс со своим конвейером, тестовая выборка, скрипт, который считает метрики одной командой, отчёт с таблицей и тремя провалами.

**Что сдаётся.**

| Файл | Содержание | Критерий |
|---|---|---|
| `src/search_bm25.py` | индекс с конвейером (токены, стоп-слова, основы), BM25 с параметрами k1, b и полями документа. По образцу лекции, без библиотек поиска | классы `Index` и `Pipeline`, стемминг работает, k1 и b задаются |
| `kg/queries.csv` | 15–20 запросов с релевантными документами и градациями 1–2. Первые запросы суть вопросы исследователя из задания 1, остальные разной формы: термин, номер, вопрос целиком, перефразировка | все релевантные есть в корпусе, не меньше трёх запросов без общих слов с названиями релевантных документов |
| `scripts/eval_search.py` | точность@5, полнота@5, MRR, NDCG@10 для двух конвейеров и двух ранжирований | печатает таблицу одной командой |
| `kg/SEARCH.md` | таблица метрик из скрипта, три запроса, где поиск проваливается, с причиной (синонимия, перефразировка, формула, связи, конвейер), решения конвейера и параметры | числа совпадают со скриптом, причины названы |
| `diary.md` | запись о выборе конвейера и параметров и о том, что показала таблица | есть запись о поиске |

**Порядок.**

1. Скопировать `search_bm25.py` из этой папки в `src/`, подключить свой корпус и его поля.
2. Собрать `kg/queries.csv` до того, как увидена выдача: пять вопросов исследователя, затем 10–15 новых. Разметить по смыслу: 2 отвечает на вопрос, 1 нужен для ответа.
3. Запустить `python3 scripts/eval_search.py --per-query`: четыре варианта и таблица по запросам.
4. Найти три провала в таблице по запросам, объяснить причину каждого. Для одного запроса напечатать вклады слов и посчитать NDCG@3 вручную со сверкой.
5. Записать решения в `kg/SEARCH.md` и `diary.md`.
6. `python3 scripts/check_l5.py` до 21 из 21.

**Типичные ошибки.** Запросы, повторяющие названия документов. Метрика без k. Провал без причины. Разные конвейеры для запроса и индекса. Стоп-слово «не» в списке. Таблица в отчёте получена не скриптом.

**Образец.** В `../lecture_3/starter/` задание выполнено на корпусе «Правила зачёта»: 15 запросов, таблица четырёх вариантов, три провала. Один запрос повторяет название документа нарочно. На 12 записях нормализация сработала в обе стороны, полнота выросла и MRR упал, и это записано в отчёте как пример чтения таблицы.
